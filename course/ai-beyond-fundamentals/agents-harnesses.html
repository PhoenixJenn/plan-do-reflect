Module 5 · Agents & Harnesses

Agents & Harnesses

Module 4 measured and guarded a system that answers one question at a time. This module gives it autonomy: a model in a loop with tools and state, working through a task that takes many steps. You'll build that loop from scratch, then do the harder and more valuable part, which is the system around the model: the limits that stop it, the state that lets it survive a crash, the permissions that keep it from doing damage, and the history that lets you debug it. The overview above makes the case for harness engineering; this lesson is where you build one.

Agent behavior is the least repeatable thing in this course, because the model chooses its own steps. So this lesson leans on one technique: wherever possible, the model is replaced by a scripted stand-in that fails in known ways, so you can test the harness deterministically and for free. Several labs below were verified that way, and each says plainly what was and wasn't run against a live model. The live-model runs are yours to record.

Concepts

An agent is a model in a loop

Strip away the vocabulary and an agent is a short program: ask the model what to do next; if it asks for a tool, run the tool and show it the result; repeat until it answers in plain text. That's the whole idea, and it's the loop you wrote by hand in Module 2, Lab 3. What changes at agent scale is everything around the loop: how long it can run, what it can touch, what happens when it fails. The research behind the pattern is Yao et al., ReAct: Synergizing Reasoning and Acting in Language Models (ICLR 2023), which showed that interleaving reasoning with actions beats either alone.

Anthropic's Building effective agents draws a line worth keeping: a workflow follows steps you wrote in code, an agent lets the model choose its own steps. Workflows are more predictable and cheaper; agents handle open-ended problems you can't script. Start with the simplest thing that works and add autonomy only where a fixed script fails.

Tools are contracts, and failures are information

A tool is a function plus a description the model reads to decide when to use it. The description is the interface: a vague one ("handles requests") makes the model guess, and Lab 7 has you watch that happen. A good tool has a clear purpose, predictable output, and an explicit failure state.

Two habits matter. First, return errors as text the model can read ("ERROR: path is outside the workspace") instead of crashing the program, because a model that sees why something failed can often route around it. Second, never run model-written text as code. Module 2's calculator used a bare eval(); this module's walks the parsed expression and allows only numbers and arithmetic, because text a model produced can contain anything.

Three patterns, and when each pays

Sequential (Anthropic calls it prompt chaining): each step feeds the next. Simple and debuggable, but slow, and a mistake early on travels downstream. Parallel: independent pieces are handled at the same time and merged. Fast, but the merge step only sees the summaries, never the originals, so detail can be lost. Loop (evaluator-optimizer): draft, critique against the source, revise, stop when the critic is satisfied or a round cap is hit. It buys quality at the cost of extra calls.

Which one wins depends on the task, which is why Lab 2 measures all three on the same inputs and scores them on facts retained, a count your code can compute with no judge at all.

Coordinators and sub-agents

A coordinator splits a big question into independent parts, hands each to a sub-agent that starts with a fresh, empty context, and merges what comes back. The gain is isolation: each sub-agent works on one narrow thing without the others' text crowding its window, and they can run at once. Anthropic described this design, and its costs, in How we built our multi-agent research system: it works well for broad research that splits cleanly, and it uses many times more tokens than a single chat, so it isn't free.

The merge is where these systems quietly go wrong. A coordinator that is allowed to "synthesize" will sometimes add facts nobody found. Lab 3 constrains the merge to the findings and keeps the citations attached; the project adds a check that every citation in the final report is one a tool actually returned.

Durable state: assume it will crash

A run that takes minutes and many paid calls will eventually be interrupted by a crash, a deploy, a closed laptop. If the only record is the conversation in memory, you start over and pay again. The fix is a progress file: after every completed step, write the plan and the results to disk, and on startup load the file and skip what's done.

Two details separate a progress file that works from one that corrupts. Write atomically: write to a temporary file, then rename it over the real one, because a crash mid-write then leaves either the old file or the new one, never half of one. And serialize concurrent writers: when three sub-agents finish at different moments and all save to the same file, they need a lock, or their temp files collide. We hit exactly that bug building this module's project.

MCP: one way to expose tools to any client

The Model Context Protocol (introduced by Anthropic in November 2024 and now an open specification at modelcontextprotocol.io) standardizes how an application offers tools, data and prompts to an AI client. You write a server that declares tools with typed arguments; any compatible client can list them and call them, with no custom integration per pair. Locally a client launches the server as a child process and talks to it over standard input and output; remote servers use HTTP.

It's a young protocol and the SDKs move. This lesson's code uses the Python SDK's 2.x API, where the server class is MCPServer imported from mcp.server.mcpserver. Many older tutorials show FastMCP from mcp.server.fastmcp, which the 2.x SDK renamed; if you hit an ImportError, check pip show mcp first.

Limits and approval belong to the harness

A loop needs five ways to stop that don't depend on the model deciding to: a step cap, a dollar budget, a wall-clock timeout, a per-tool timeout, and repeat detection (the same call over and over is not progress; escalate to a person). And any action that can't be undone needs approval outside the model: the model proposes, a policy checks, a human confirms, a tool executes. Asking the model to approve its own risky action is asking one probabilistic system to be both the driver and the brakes.

A subtle limit worth knowing: you can't kill a stuck thread in Python, only stop waiting for it. A per-tool timeout therefore returns control to the loop, but the abandoned work may still be running. For tools that can truly hang, run them in a separate process you can terminate.

Brain, hands, history, and the failures you can name

Module 5's overview describes the harness as everything around the model. This lesson splits it into three components you can see in the code: the brain (one function that asks the model what to do next; brain.py), the hands (the tools and their permission flags; tools.py), and the history (an append-only record of every step; harness.History). Keeping them separate is what lets you fake the brain in a test, deny a tool without touching the model, and replay a run from its log.

The overview's table maps seven failure types to seven harness fixes. Lab 7 makes that table physical: seven reproducible failures in a sandbox, and a harness you repair until all seven stay fixed. It's the same move as a bug report with a failing test: name the failure class, change the system, and prove the change with a rerun.

  3. Create agent/brain.py. This is the only file that talks to the model. It also keeps a running token count so later labs can report cost.
    """The brain: one function that asks the model what to do next. Nothing else lives here, so the model can be swapped (or faked in a test) without touching the loop.""" import os from dotenv import load_dotenv load_dotenv() from anthropic import Anthropic MODEL = "claude-sonnet-5" _client = Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"]) USAGE = {"input": 0, "output": 0} # running totals across every call in this process def think(system, messages, tools=None, max_tokens=800): kwargs = {"tools": tools} if tools else {} resp = _client.messages.create(model=MODEL, max_tokens=max_tokens, system=system, messages=messages, **kwargs) USAGE["input"] += resp.usage.input_tokens USAGE["output"] += resp.usage.output_tokens return resp def complete(prompt, system="You are a precise assistant.", max_tokens=800): """One plain-text call, no tools. Returns just the text.""" resp = think(system, [{"role": "user", "content": prompt}], None, max_tokens) return "".join(b.text for b in resp.content if b.type == "text")
  4. Create agent/tools.py with two tools, search and a calculator. The calculator parses the expression and permits only numbers and arithmetic; it does not call eval(). Each tool is a function plus the schema the model reads.
    import ast, operator from search_tool import search_docs _OPS = {ast.Add: operator.add, ast.Sub: operator.sub, ast.Mult: operator.mul, ast.Div: operator.truediv, ast.USub: operator.neg} def calculate(expression): """Arithmetic only. We walk the parsed expression instead of calling eval(), because eval() on text a model produced can run anything.""" def walk(node): if isinstance(node, ast.Constant) and isinstance(node.value, (int, float)): return node.value if isinstance(node, ast.BinOp) and type(node.op) in _OPS: return _OPS[type(node.op)](walk(node.left), walk(node.right)) if isinstance(node, ast.UnaryOp) and type(node.op) in _OPS: return _OPS[type(node.op)](walk(node.operand)) raise ValueError("only + - * / and numbers are allowed") return walk(ast.parse(expression, mode="eval").body) TOOLS = { "search_docs": { "fn": search_docs, "schema": {"name": "search_docs", "description": "Search the Larkfield product manuals. Returns passages tagged [file.pdf p.N].", "input_schema": {"type": "object", "properties": { "query": {"type": "string"}}, "required": ["query"]}}}, "calculate": { "fn": calculate, "schema": {"name": "calculate", "description": "Evaluate an arithmetic expression such as '282 * 1.1'.", "input_schema": {"type": "object", "properties": { "expression": {"type": "string"}}, "required": ["expression"]}}}, }

  5. Create agent/loop.py: the 60-line agent. It calls the model, runs any tool the model asks for, appends the result, and repeats until the model answers in text. Two limits exist from the first line, a step cap and a token budget, and a tool error is passed back to the model as text instead of crashing the run.
    import sys from brain import think from tools import TOOLS class StepLimit(Exception): pass class BudgetExceeded(Exception): pass def run_agent(task, tools, system="You are a careful research assistant. Use tools to find facts, " "and cite the [file p.N] tags you rely on.", max_steps=8, max_tokens_total=40_000, think=think, verbose=True): messages = [{"role": "user", "content": task}] schemas = [t["schema"] for t in tools.values()] used = 0 for step in range(1, max_steps + 1): resp = think(system, messages, schemas) used += resp.usage.input_tokens + resp.usage.output_tokens if used > max_tokens_total: raise BudgetExceeded(f"{used:,} tokens used, limit {max_tokens_total:,}") calls = [b for b in resp.content if b.type == "tool_use"] if not calls: text = "".join(b.text for b in resp.content if b.type == "text") return text, {"steps": step, "tokens": used} # Store the assistant turn as plain dicts so the history can be saved as JSON later. messages.append({"role": "assistant", "content": [ {"type": "tool_use", "id": c.id, "name": c.name, "input": c.input} if c.type == "tool_use" else {"type": "text", "text": c.text} for c in resp.content]}) results = [] for c in calls: try: out = tools[c.name]["fn"](**c.input) except Exception as e: # a tool failure is information, not a crash out = f"ERROR: {type(e).__name__}: {e}" if verbose: print(f" step {step}: {c.name}({c.input}) -> {str(out)[:80]!r}") results.append({"type": "tool_result", "tool_use_id": c.id, "content": str(out)}) messages.append({"role": "user", "content": results}) raise StepLimit(f"no final answer after {max_steps} steps") if __name__ == "__main__": q = sys.argv[1] if len(sys.argv) > 1 else ( "What is the maximum pressure of the Delta Sensor in bar, and what is that as a " "number of kilopascals? (1 bar = 100 kPa)") answer, stats = run_agent(q, TOOLS) print("\n" + answer, "\n", stats)

  1. Create agent/patterns.py. It takes five of Module 3's manuals (the readable ones, not the scans) and summarizes them three ways: sequential (one running summary updated manual by manual), parallel (five summaries at once, then a merge), and loop (draft, critique against the source, revise, up to three rounds). Each is scored by counting how many of the manuals' known facts survive, where a fact only counts if it appears on a line naming its own product, so another product's "12 months" can't earn credit.
    """Summarize five manuals three ways and score each by how many of the 15 key facts survive.""" import json, re, time from concurrent.futures import ThreadPoolExecutor import pypdf import brain from brain import complete # Five readable (not scanned) manuals, and the three facts each one contains. questions = json.load(open("rag/questions.json")) docs = [] for q in questions: if "_scan" not in q["doc"] and q["doc"] not in [d["doc"] for d in docs] and len(docs) < 5: docs.append({"doc": q["doc"], "product": re.sub(r"^\d+_|\.pdf", "", q["doc"]).replace("_", " "), "facts": sorted({x["answer"] for x in questions if x["doc"] == q["doc"] and x["answer"][0].isdigit()})}) for d in docs: d["text"] = "\n".join(p.extract_text() for p in pypdf.PdfReader(f"rag/corpus/{d['doc']}").pages) KEEP = "Always keep each product's name, warranty length, maximum pressure and recalibration interval." def sequential(): """One running summary, updated manual by manual. Each step needs the one before it.""" summary = "" for d in docs: summary = complete(f"Current summary:\n{summary}\n\nNew manual:\n{d['text']}\n\n" f"Update the summary to include this manual. {KEEP}") return summary def parallel(): """Summarize each manual independently at the same time, then merge. Fast, but the merge step only sees the summaries, never the originals.""" with ThreadPoolExecutor(max_workers=5) as pool: parts = list(pool.map(lambda d: complete(f"Summarize this manual in 3 sentences. {KEEP}\n\n{d['text']}"), docs)) return complete("Merge these into one short summary, one line per product:\n\n" + "\n\n".join(parts)) def loop(max_rounds=3): """Draft, critique against the source, revise. Stops early when the critic finds nothing.""" source = "\n\n".join(d["text"] for d in docs) draft = complete(f"Summarize these five manuals, one line per product. {KEEP}\n\n{source}") for _ in range(max_rounds): critique = complete(f"Source:\n{source}\n\nSummary:\n{draft}\n\nList every product fact (warranty, " f"pressure, recalibration interval) that is missing or wrong in the summary. " f"If nothing is missing or wrong, reply exactly: OK") if critique.strip() == "OK": break draft = complete(f"Source:\n{source}\n\nSummary:\n{draft}\n\nProblems:\n{critique}\n\nRewrite the summary fixing these problems.") return draft def score(summary): """A fact only counts if it appears on a line that names its own product, so '12 months' belonging to a different product can't earn credit.""" lines = [l.lower() for l in summary.splitlines() if l.strip()] got = total = 0 for d in docs: own = " ".join(l for l in lines if d["product"] in l) for fact in d["facts"]: total += 1 got += fact.lower() in own return got, total if __name__ == "__main__": for name, fn in [("sequential", sequential), ("parallel", parallel), ("loop", loop)]: brain.USAGE.update(input=0, output=0) t0 = time.time() summary = fn() got, total = score(summary) print(f"{name:11s} {time.time() - t0:5.1f}s tokens={brain.USAGE['input'] + brain.USAGE['output']:7,} facts {got}/{total}")

  1. Create agent/subagents.py. The coordinator asks the model to split the question into three independent sub-questions (as JSON). Each goes to a sub-agent: a fresh run_agent call with its own message list, only the search tool, and an instruction to cite or admit it found nothing. The sub-agents run at the same time. The merge step is told to use only their findings and keep every citation attached.
    import json, sys from concurrent.futures import ThreadPoolExecutor from brain import complete from loop import run_agent from tools import TOOLS SUB_SYSTEM = ("You research ONE narrow question using search_docs. Answer only from search results, " "cite every fact as [file.pdf p.N], and say so plainly if the manuals don't contain it.") def plan(question, n=3): """The coordinator's whole job: split the question into independent sub-questions.""" raw = complete(f"Split this research question into exactly {n} independent sub-questions that can be " f"answered separately. Reply only JSON: {{\"sub_questions\": [\"...\"]}}\n\n{question}") return json.loads(raw[raw.index("{"): raw.rindex("}") + 1])["sub_questions"][:n] def research(sub_question): """One sub-agent: its own fresh message list, so nothing from the other sub-agents leaks in.""" answer, stats = run_agent(sub_question, {"search_docs": TOOLS["search_docs"]}, system=SUB_SYSTEM, max_steps=5, verbose=False) return {"question": sub_question, "answer": answer, **stats} def coordinate(question): subs = plan(question) with ThreadPoolExecutor(max_workers=len(subs)) as pool: results = list(pool.map(research, subs)) findings = "\n\n".join(f"Q: {r['question']}\nA: {r['answer']}" for r in results) report = complete("Write a short report answering the original question using ONLY the findings below. " "Keep every [file.pdf p.N] citation attached to its fact. Add no new facts.\n\n" f"Original question: {question}\n\nFindings:\n{findings}", max_tokens=1000) return report, results if __name__ == "__main__": q = sys.argv[1] if len(sys.argv) > 1 else ( "Compare the Delta Sensor and the Cobalt Pump on warranty length, maximum pressure, " "and recalibration interval.") report, results = coordinate(q) for r in results: print(f"- sub-agent ({r['steps']} steps, {r['tokens']:,} tokens): {r['question']}") print("\n" + report)

  1. Create agent/progress.py. It saves the plan, then each sub-question's result, to agent/state/<run_id>.json after every step. The save writes a temp file and renames it into place, so a crash can't leave half a file. On startup it loads the file and skips whatever is done. A crash_after flag kills the process with no cleanup, like a force-quit.
    """A research run that writes its progress to disk after every step, so a crash costs one step.""" import json, os, sys from pathlib import Path from subagents import plan, research from brain import complete STATE = Path("agent/state"); STATE.mkdir(parents=True, exist_ok=True) def save(path, state): """Write to a temp file, then rename. A crash mid-write can't leave a half-written state file, because the rename is atomic: the file is either the old version or the new one.""" tmp = path.with_suffix(".tmp") tmp.write_text(json.dumps(state, indent=1)) os.replace(tmp, path) def run(run_id, question, crash_after=None): path = STATE / f"{run_id}.json" state = json.loads(path.read_text()) if path.exists() else {"question": question, "plan": None, "done": {}} if state["plan"] is None: state["plan"] = plan(question); save(path, state) # step 0: the plan itself is saved print("planned:", state["plan"]) else: print(f"resuming: {len(state['done'])}/{len(state['plan'])} sub-questions already done") for i, sub in enumerate(state["plan"]): if str(i) in state["done"]: continue # finished before the crash: skip state["done"][str(i)] = research(sub); save(path, state) print(f" done {i + 1}/{len(state['plan'])}: {sub}") if crash_after is not None and len(state["done"]) >= crash_after: print("simulated crash"); os._exit(1) # no cleanup, like a killed process findings = "\n\n".join(f"Q: {state['done'][str(i)]['question']}\nA: {state['done'][str(i)]['answer']}" for i in range(len(state["plan"]))) state["report"] = complete(f"Write a short cited report using ONLY these findings:\n\n{findings}") save(path, state) return state["report"] if __name__ == "__main__": crash = int(sys.argv[3]) if len(sys.argv) > 3 else None print(run(sys.argv[1], sys.argv[2], crash))

  1. Extend agent/tools.py with three workspace tools: list_files, read_file and delete_file, all confined to agent/workspace/. delete_file is flagged "risky": True. Path handling resolves each path and refuses anything outside the folder.

Flag duplicates, stalls and conflicts, and bother a human only when a judgment call is needed.""" import json, re, time from pathlib import Path from itertools import combinations from brain import complete STALL_MINUTES = 30 def words(s): return set(re.findall(r"[a-z0-9]+", s.lower())) def duplicates(runs): """Two runs working on (nearly) the same sub-question are doing the work twice.""" flags = [] for (a, ra), (b, rb) in combinations(runs.items(), 2): for qa in ra["plan"] or []: for qb in rb["plan"] or []: wa, wb = words(qa), words(qb) if wa and wb and len(wa & wb) / len(wa | wb) >= 0.8: flags.append(f"DUPLICATE: '{a}' and '{b}' both plan: {qa!r}") return flags def stalled(paths, now=None): now = now or time.time() out = [] for p in paths: s = json.loads(p.read_text()) unfinished = s["plan"] and len(s["done"]) < len(s["plan"]) and "report" not in s if unfinished and (now - p.stat().st_mtime) > STALL_MINUTES * 60: out.append(f"STALLED: '{p.stem}' unfinished and untouched for over {STALL_MINUTES} minutes") return out def review(state_dir="agent/state", diary="agent/diary.md", out="agent/escalations.md", complete=complete): paths = sorted(Path(state_dir).glob("*.json")) runs = {p.stem: json.loads(p.read_text()) for p in paths} flags = duplicates(runs) + stalled(paths) summary = "\n\n".join(f"Run {name}: {r['question']}\n" + "\n".join( f"- {r['done'][k]['question']} => {r['done'][k]['answer'][:300]}" for k in sorted(r["done"])) for name, r in runs.items()) diary_text = Path(diary).read_text() if Path(diary).exists() else "(no diary)" raw = complete("You review work done by several research agents. Find places where two runs reached " "CONTRADICTORY answers to the same question, or where the diary contradicts a run. Say " "needs_human=true only if resolving it requires a judgment call a person should make. " 'Reply only JSON: {"conflicts": ["..."], "needs_human": true/false, "reason": "..."}\n\n' f"Diary:\n{diary_text}\n\nRuns:\n{summary}") verdict = json.loads(raw[raw.index("{"): raw.rindex("}") + 1]) if flags or verdict["conflicts"] or verdict["needs_human"]: lines = ["# Escalations", ""] + [f"- {f}" for f in flags] + [f"- CONFLICT: {c}" for c in verdict["conflicts"]] if verdict["needs_human"]: lines += ["", f"**Needs your call:** {verdict['reason']}"] Path(out).write_text("\n".join(lines)) return lines Path(out).unlink(missing_ok=True) return [] if __name__ == "__main__": result = review() print("\n".join(result) if result else "nothing to escalate")
    python agent/chief_of_staff.py
  3. Read agent/escalations.md. For each flag, decide whether you'd have wanted to be interrupted. Tune the threshold or the model's instructions until the flags are ones you'd act on.
  4. Run it again after finishing every run. It should report nothing to escalate. A chief of staff that escalates everything is just another inbox.
Check: the deterministic part we tested with hand-built state files: two runs planning "Warranty on the Delta Sensor" and "warranty on the delta sensor?" were flagged as a duplicate (word overlap ignores case and punctuation), an unfinished run untouched for an hour was flagged as stalled, and once every run was finished with distinct questions the escalation file was removed and the report was empty. The model-judged conflict check was not run against a live model, so its sensitivity is yours to measure: seed one deliberate contradiction (two runs, opposite answers) and confirm it's caught, and seed none and confirm it stays quiet.

Project

Project · Research agent with sub-agents

The labs built the parts separately. This project assembles them into one agent you could hand to someone: the coordinator plans, sub-agents run under the harness's limits, progress is saved after every sub-agent, the report is checked against what the tools actually returned, and every run leaves a full history and a change receipt.

  1. Create agent/research.py. Read it before running it; it uses the three components on purpose. The brain is brain.py (and can be swapped for a fake in a test), the hands are tools.py, the history is harness.History, one per sub-agent plus one for the coordinator. After the sub-agents finish and the report is written, a check confirms every [file p.N] citation in it is one a search tool actually returned in some sub-agent's history. If not, it gets one bounded rewrite, then reports honestly either way. The receipt records the context sources, tools used, check results, retries, tokens and a rollback point.
    """Project: a research agent. Brain = brain.py, hands = tools.py, history = harness.History.""" import json, os, re, subprocess, sys import threading from concurrent.futures import ThreadPoolExecutor from pathlib import Path import brain, harness from harness import Limits, History, run_agent from subagents import SUB_SYSTEM from tools import TOOLS CITE = re.compile(r"\[([^\]]+?\.pdf) p\.(\d+)\]") def save(path, state): tmp = Path(str(path) + ".tmp"); tmp.write_text(json.dumps(state, indent=1)); os.replace(tmp, path) def tags_in_history(history_path): """Every [file p.N] tag a tool actually returned: the only citations the report may use.""" found = set() for line in open(history_path): e = json.loads(line) if e["kind"] == "tool" and e["name"] == "search_docs": found |= {(d, p) for d, p in CITE.findall(e["output"])} return found def git_head(): try: return subprocess.run(["git", "rev-parse", "HEAD"], capture_output=True, text=True).stdout.strip() or None except FileNotFoundError: return None def research(run_id, question, limits=None, think=brain.think, complete=brain.complete, crash_after=None): limits = limits or Limits(max_steps=6, timeout_s=180) run_dir = Path("agent/runs") / run_id; run_dir.mkdir(parents=True, exist_ok=True) state_path = run_dir / "state.json" state = json.loads(state_path.read_text()) if state_path.exists() else {"question": question, "plan": None, "done": {}} top = History(run_id) # the coordinator's own history retries = 0 lock = threading.Lock() # three sub-agents finish at different times but share one state file if state["plan"] is None: raw = complete(f'Split this question into exactly 3 independent sub-questions. Reply only JSON: ' f'{{"sub_questions": ["..."]}}\n\n{question}') state["plan"] = json.loads(raw[raw.index("{"): raw.rindex("}") + 1])["sub_questions"][:3] save(state_path, state); top.add("plan", sub_questions=state["plan"]) else: top.add("resume", done=sorted(state["done"])) def sub(i): if str(i) in state["done"]: return state["done"][str(i)] r = run_agent(state["plan"][i], {"search_docs": TOOLS["search_docs"]}, SUB_SYSTEM, limits, history=History(f"{run_id}/sub{i}"), think=think) with lock: # one writer at a time, or the temp files collide state["done"][str(i)] = r; save(state_path, state) # progress file: written after every sub-agent if crash_after is not None and len(state["done"]) >= crash_after: os._exit(1) return r with ThreadPoolExecutor(max_workers=3) as pool: results = list(pool.map(sub, range(len(state["plan"])))) findings = "\n\n".join(f"Q: {state['plan'][i]}\nA: {r.get('answer') or '(no answer: ' + r['status'] + ')'}" for i, r in enumerate(results)) report = complete("Write a short report answering the original question using ONLY these findings. Keep every " f"[file.pdf p.N] citation attached to its fact.\n\nQuestion: {question}\n\n{findings}") # Sensor before autonomy: every citation in the report must be one a tool actually returned. retrieved = set().union(*[tags_in_history(Path("agent/runs") / f"{run_id}/sub{i}" / "history.jsonl") for i in range(len(state["plan"]))]) cited = set(CITE.findall(report)) bad = sorted(cited - retrieved) check = {"citations_found": len(cited), "citations_not_retrieved": bad, "passed": bool(cited) and not bad} if not check["passed"] and retries < 1: # one bounded retry, then report honestly retries += 1 report = complete(f"Rewrite this report. Remove or fix these unsupported citations: {bad or 'there are none; add citations'}.\n\n{report}") cited = set(CITE.findall(report)); bad = sorted(cited - retrieved) check = {"citations_found": len(cited), "citations_not_retrieved": bad, "passed": bool(cited) and not bad} (run_dir / "report.md").write_text(report) receipt = { "question": question, "model": brain.MODEL, "context_sources": sorted(f"{d} p.{p}" for d, p in retrieved), "tools_used": sum(1 for i in range(len(state["plan"])) for l in open(Path("agent/runs") / f"{run_id}/sub{i}" / "history.jsonl") if json.loads(l)["kind"] == "tool"), "sub_agent_status": {i: r["status"] for i, r in enumerate(results)}, "checks": check, "retries": retries, "tokens": sum(r.get("tokens", 0) for r in results), "accepted_artifact": str(run_dir / "report.md"), "rollback_point": {"git_commit": git_head(), "state_file": str(state_path)}, } (run_dir / "receipt.json").write_text(json.dumps(receipt, indent=1)) return report, receipt if __name__ == "__main__": run_id = sys.argv[1] q = sys.argv[2] crash = int(sys.argv[3]) if len(sys.argv) > 3 else None report, receipt = research(run_id, q, crash_after=crash) print(report); print(json.dumps(receipt, indent=1))

What testing the project found

The first version of this project's progress save crashed under real concurrency: three sub-agents finishing at nearly the same moment all wrote the same temporary file, and one rename failed because another had already moved it. A lock around "update state and save" fixed it. It only showed up because the sub-agents genuinely ran in parallel. A single-threaded test would have passed, which is the argument for testing a harness with the real concurrency, not a simplified one.

Done when:

  • It runs from your own loop, with no agent framework (adopting one afterward is fine once you know what it does for you).
  • Each of the five limits demonstrably stops a run, and the approval gate refuses an unapproved risky action.
  • It resumes after an interruption, and only the unfinished work reruns.
  • Brain, hands and history are separate components you can point to, and the brain can be faked in a test.
  • Every run saves its full history and a receipt with context sources, tools used, check results, retries, cost and a rollback point.
  • A report with an unsupported citation is caught before it's accepted.
